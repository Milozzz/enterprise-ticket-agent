# Tool Gateway

Tool Gateway 是 Agent 节点与业务工具之间的统一执行边界。它不会替代退款流程里已有的业务逻辑，也不会替代 DB/Redis 幂等保护，而是把工具调用统一收口，让每一次工具执行都具备权限校验、风险分级、dry-run、幂等元数据和审计上下文。

## 职责

- 工具注册：统一维护工具名称、业务动作、风险等级、副作用类型和幂等字段。
- 权限校验：工具真正执行前，先检查当前执行者角色是否有权限调用对应动作。
- Dry-run：对有副作用的工具，可以只返回计划执行的信息，不真正调用业务工具。
- 审计封装：记录执行者角色、请求方角色、trace/thread ID、耗时、风险等级、副作用类型、成功状态和幂等 key。
- 稳定集成点：Agent 节点通过 Tool Gateway 调用工具，同时保留原有 DB/Redis 幂等机制作为最终安全兜底。

## 当前接入工具

| 工具 | 副作用类型 | 风险等级 | 允许执行角色 |
| --- | --- | --- | --- |
| `lookup_order` | 读取 | 低 | user / agent / manager |
| `check_risk_level` | 决策 | 中 | user / agent / manager |
| `execute_refund` | 写操作 | 高 | agent / manager |
| `send_notification` | 外部通知 | 中 | agent / manager |

## 面试表述

这个设计的核心是把“用户意图”和“工具执行权限”分离。用户可以发起退款请求，但真正的退款工具不是由用户角色直接调用，而是由 Agent 服务身份在风控、HITL 审批、权限校验都通过后，通过 Tool Gateway 执行。

因此，高风险工具不会暴露给 LLM 或用户直接调用；所有工具调用都会先经过统一网关，留下可追踪、可审计、可复盘的执行记录。这更接近企业生产系统里对 Agent 工具调用的治理方式。
